# BeSpoke comprehensive QA and repair — September 24, 2026

## Scope and acceptance

This run covers the guided visual-design builder on `codex/bespoke-guided-builder`:
editor controls, workflow, durable state and recovery, rendering, accessibility,
service/validation boundaries, generated artifacts, browser engines and local performance.
It does not authorize curriculum authoring, hosted rollout, real Send, or a lesson build.
Every automated session uses synthetic selections, a fresh browser context and an
ephemeral loopback server. The live Safari tab and persistent preview draft are excluded.

Three independent agents audited workflow/state, visual/accessibility behavior,
and model/service/schema/security contracts. After reproductions, the workflow
agent owned app repairs; the visual agent owned shared renderer repairs; the
contract agent independently checked imports. The root integrated tests, reviewed
diffs/screenshots, ran cross-engine and performance checks, and ran the full gate.

| Area | Benchmark / acceptance criterion | Coverage |
| --- | --- | --- |
| Choices and cumulative preview | Exact selected values survive navigation, Undo, reload, backup, save and reopen; no unsolicited color substitution | Existing end-to-end suite plus concurrency/recovery regressions |
| Presets and session preference | All six presets editable; opt-out changes only on checked Apply; correct Cancel/Escape/focus and fresh-session behavior | Desktop/phone, unavailable session storage, separate tabs |
| Validation and imports | Browser rejects malformed payload before changing draft; Node/Python agree on structure, exact values and contrast advisories | Adversarial payloads, valid palette/font rotations, atomic rejected imports |
| Shared persistence | Revision checks, identical-mutation retry, no unrequested write after replacing a draft; recovery preserves the actual draft being replaced | Held responses, edits during save, lost response, stale/multiple tabs, reload |
| Authorization and security | Rejected credentials/lesson access cannot read or write store; sample text remains inert; closed schemas reject unknown/prototype keys | Synthetic service tests, malformed HTTP, escaped hostile sample strings |
| Generated output | Sample and canonical markup/CSS reflect same saved design, title geometry, video borders and responsive cards | Existing parity matrices plus new narrow-canvas/enlarged-text geometry |
| Reflow and readable geometry | No horizontal document overflow at 320 CSS px; meaningful text remains contained and usable in its actual preview pane | 320/390/768/1100/1920 widths, short viewport, landscape, every role and selected long-copy stress cases |
| Enlarged text | 200% text resize retains meaningful content and operation; decorative watermark cannot overlap following content | Editor and generated/canonical cards/dividers |
| Accessibility | No new editor axe A/AA violations; labels, focus return, keyboard operation; target size at least 24 CSS px or valid spacing exception | Ten steps, responsive states and dialogs; explicit low-contrast previews separately documented |
| Browser engines | Same behavior/geometry assertions on isolated Chromium and WebKit | Guided workflow, title/video matrix and new QA scripts |
| Performance | Record repeatable local timings and asset/network errors; distinguish lab proxy from field INP | Fresh-context desktop/phone loads and 30 paint interactions per viewport |
| Repository integration | Full required quality gate, schema/library sync, generated contracts, unchanged lesson fingerprints and existing a11y ratchet | Baseline and final integrated gate |

The reflow and resize criteria follow [WCAG reflow](https://www.w3.org/WAI/WCAG21/Understanding/reflow)
and [200% text resizing](https://www.w3.org/WAI/WCAG22/Techniques/general/G179.html).
Target sizing uses the [WCAG 2.2 24px minimum with spacing exceptions](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum);
44px is a preferred usability size, not the AA minimum.
[INP's good threshold is 200ms](https://web.dev/articles/inp), but the local
click-to-second-animation-frame measurement here is only a rendering proxy,
not field INP or a Core Web Vitals certification.

Coverage is risk-based and pairwise. It is not every possible combination of every
palette, font, layout and content string. Contrast remains advisory: deliberately
low-contrast selected slide colors are valid and preserved. Editor chrome and
ordinary accessible samples are scanned separately from such intentional samples.

## Confirmed findings and repairs

| ID / severity | Reproduction and expected behavior | Observed cause and repair |
| --- | --- | --- |
| F-W1 / P1 | Hold a successful Save response, choose New draft, then release it. The new draft must remain local until explicitly saved. | Older completion cleared the new draft's autosave pause and caused an unintended shared revision. Draft identity now fences asynchronous completion. |
| F-W2 / P1 | Two same-origin tabs retain different designs; another tab saves, then the unsaved tab loads latest. Recovery must contain the design actually being replaced. | Recovery read shared localStorage, which could belong to the other tab. It now snapshots the current tab's in-memory draft. |
| F-C1 / P2 | Import unknown/prototype keys, a lone surrogate, an impossible date, or a title exceeding the model's UTF-16 limit. Reject atomically and leave editor usable. | Browser schema lookup accepted inherited keys and omitted shared structural/Unicode/calendar checks for draft imports. Invalid design could be assigned before render failed. Browser validation now precedes mutation. |
| F-V1 / P2 | At 768px viewport choose four numbered boxes Across. Boxes must reflow to the actual preview pane. | Viewport breakpoints left four columns in a 367px canvas, with text widths near 4.9px and up to 23,204px height. Shared container queries now reduce columns according to canvas width and enlarged text. |
| F-V2 / P2 | Enlarge text to 200% on a narrow divider with watermark. Only meaningful copy may grow the slide. | Fixed rem-sized decoration wrapped and extended beneath the slide. The watermark now stays on one bounded, canvas-sized decorative line. |
| F-V3 / P2 | Generate long cards in the actual canonical wrapper, particularly at 844×390. All copy must be reachable by normal vertical scrolling. | Existing template centering positioned the beginning above scrollTop=0 (heading at -3600px in the original-model reproduction). Generated CSS uses safe centering so overflow starts at the reachable top; template and lessons are unchanged. |
| F-C2 / P2 | Convert a valid v1 title containing supplementary Unicode characters at the sample limit. Converted output must remain valid Unicode and save successfully. | UTF-16 slicing could split a surrogate pair, producing a converted draft rejected by service validation. Migration truncation now preserves complete Unicode characters within the existing size limits. |
| F-V4 / P2 | Open Lesson & team in WebKit at 390px with 200% text. Native select content must not widen the document. | Option text overflow propagated beyond the otherwise bounded select, making the page 519px wide. Scoped select overflow containment preserves the native control and keyboard selection. |
| F-W3 / P3 | Request history, start a new draft, then release the old response. A closed history panel must report closed state. | Independent repair review caught early-return branches hiding the panel while retaining an expanded label/ARIA state. All closure branches now reset the panel, label and aria-expanded together. |

Severity is impact-based: P1 indicates unintended durable write or loss of the
only current draft; P2 indicates broken import/recovery feedback or materially
unusable rendering in a supported viewport; P3 indicates inconsistent disclosure
feedback without draft loss. Reproductions and targeted regressions
use synthetic data only.

## Local performance baseline

`benchmark-bespoke.mjs` ran sequentially after the integrated gate, using five
fresh contexts at each width and 30 actual palette clicks per width, with no
CPU/network throttling. Ready time means the initialized editor controls, slide
and local-preview notice are present. It does not mean all possible font choices
have loaded. The click proxy runs from the capture listener to the second animation
frame; it excludes input delay. Small local samples support a repeatable baseline,
not a claim about classroom devices, hosted networks or field percentiles.

| Engine / width | Ready p75 | Ready max | Paint proxy p75 | Paint proxy p95 |
| --- | ---: | ---: | ---: | ---: |
| Chromium 148.0.7778.96 / 1440px | 94.4ms | 97.1ms | 32.0ms | 32.4ms |
| Chromium / 390px | 83.5ms | 86.8ms | 31.9ms | 32.6ms |
| WebKit 26.4 / 1440px | 159ms | 197ms | 48ms | 53ms |
| WebKit / 390px | 104ms | 107ms | 36ms | 38ms |

Both runs recorded zero uncaught errors, failed HTTP responses or external requests.
Chromium recorded 22 desktop / 21 phone resource entries, plus the main document,
and approximately 735 / 718KiB total decoded response bodies. These local adapter
sizes include its configuration/data responses and are not a hosted-transfer budget.
Raw timings and measurement method are retained in the two performance JSON files.

## Reproduction

```sh
bash scripts/quality.sh
BESPOKE_BROWSER=webkit node scripts/test-bespoke-builder-browser.mjs
BESPOKE_BROWSER=webkit node scripts/test-bespoke-title-layouts.mjs
BESPOKE_BROWSER=webkit node scripts/test-bespoke-video-frames.mjs
BESPOKE_BROWSER=webkit node scripts/test-bespoke-contract-qa.mjs
BESPOKE_BROWSER=webkit node scripts/test-bespoke-workflow-qa.mjs
BESPOKE_BROWSER=webkit node scripts/test-bespoke-visual-qa.mjs
node scripts/benchmark-bespoke.mjs
BESPOKE_BROWSER=webkit node scripts/benchmark-bespoke.mjs
```

Use the pinned Playwright runtime (`node node_modules/playwright/cli.js install webkit`
if missing). On macOS, isolated WebKit follows system Tab preferences. The shared
test helper uses Option-Tab for all-control keyboard traversal, as documented in
[Apple's Safari keyboard shortcuts](https://help.apple.com/safari/mac/8.0/en.lproj/cpsh003.html).
A minimal three-button page reproduced the same Tab behavior outside BeSpoke;
this was a harness/platform distinction, not an application defect. No Safari
or operating-system preference was changed.

WebKit also reports the screenshot decoder's in-memory PNG blobs as image requests.
The video harness distinguishes these from external HTTP(S) network requests and
still asserts that no external media is loaded.
